# Config/Tokens.qml + Config/Colors.json — worked examples

`Config/Tokens.qml` and `Config/Colors.json` are both generated by `phi
theme set` (S-12) from `design/tokens.common.sh` + `design/tokens.<variant>.sh`
in `phios-dotfiles`, via `design/adapters.txt` (S-20). Both are gitignored,
so a fresh clone has neither until `phi theme set dark` (or `light`) has run
once — see the top-level README.

**Split across two files** (for the "auto"
light/dark theme option needs `phi theme set` to stop forcing a full
Quickshell session reset). `Config/Tokens.qml` is `pragma Singleton`, and
rewriting a singleton's own QML SOURCE forces Quickshell to fully
re-evaluate it — destroying in-flight panel/session state — instead of a
scoped hot-reload. Colour is the only tier that actually differs between
the dark and light variant, so it moved onto `Config/Colors.json`, plain
data read by `Config/Colors.qml` via a watched `FileView`: rewriting that
file only updates a FileView's tracked content, never a singleton's source,
so a variant switch no longer resets anything. `Config/Tokens.qml` keeps
every STRUCTURAL token (typography, spacing, radius, motion, z-layers,
textures) — identical between variants, and its own source now never
changes on a switch either.

These are hand-rendered snapshots of the dark variant as
`design/tokens.dark.sh` reads today, kept here **only** as reference
documentation — the Tokens half is plain markdown, not a `.qml` file,
precisely so Quickshell's config-tree scanner never sees it as a candidate
type. (A first attempt shipped it as `Config/Tokens.example.qml`, next to
the real `Config/Tokens.qml`; Quickshell's own module scan swept it in —
with or without anything importing it — read its dotted filename's first
segment as the type name, and collided with the real `Tokens` type. `qs -p`
failed to load at all: `Config.Tokens.example - Tokens is not a type`.) The
Colors half is a plain fenced JSON block for the same reason, one step
further removed since it isn't even QML. Neither file is regenerated
automatically and both will drift from the real token files the moment
either changes — they are not a source of truth, `design/tokens.*.sh` in
`phios-dotfiles` is.

Every value is a string, units included (`"14px"`, `"120ms"`, `"1ch"`),
exactly as `design/tokens.common.sh`'s own contract requires: a consumer
that needs a bare number strips the unit itself. `Config/Appearance.qml` is
the only file allowed to read either of these directly — everything else
reads `Appearance`.

## Config/Tokens.qml (structural — identical between variants)

```qml
pragma Singleton
import Quickshell

Singleton {
    id: root

    // --- Typography --------------------------------------------------------
    readonly property string fontMono: "Source Code Pro"
    readonly property string fontReading: "Source Serif 4"
    readonly property string fontUi: "Source Sans 3"
    readonly property string fontSymbol: "Symbols Nerd Font Mono"

    // --- Size scale --------------------------------------------------------
    readonly property string fontSize0: "11px"
    readonly property string fontSize1: "13px"
    readonly property string fontSize2: "14px"
    readonly property string fontSize3: "16px"
    readonly property string fontSize4: "18px"
    readonly property string fontSize5: "21px"
    readonly property string fontSize6: "24px"

    // --- Spacing -------------------------------------------------------
    readonly property string space1: "1ch"
    readonly property string space2: "2ch"
    readonly property string space3: "3ch"
    readonly property string space4: "4ch"
    readonly property string space5: "6ch"
    readonly property string space6: "8ch"

    // --- Shape -------------------------------------------------------
    readonly property string radiusBase: "2px"
    readonly property string radiusPill: "9999px"
    readonly property string radiusSmall: "1px"
    readonly property string radiusLarge: "4px"
    readonly property string borderWidth: "1px"
    readonly property string borderWidthStrong: "1px"
    readonly property string panelPadding: "8px"
    readonly property string panelGap: "4px"
    readonly property string panelRadius: "6px"
    readonly property string sliderThickness: "4px"

    // --- User-tunable scale (identity by default) --------------------------
    readonly property string fontScale: "1"
    readonly property string spaceScale: "1"

    // --- Layering -------------------------------------------------------
    readonly property string zBase: "0"
    readonly property string zBar: "100"
    readonly property string zPopover: "200"
    readonly property string zModal: "300"
    readonly property string zTooltip: "400"
    readonly property string zNotification: "500"

    // --- Motion -------------------------------------------------------
    readonly property string motionAPeriod: "1600ms"
    readonly property string motionAEasing: "linear"
    readonly property string motionBDuration: "120ms"
    readonly property string motionBEasing: "ease-out"
    readonly property string motionBBezier: "0.25,0.46,0.45,0.94"
    readonly property string motionCTypeStep: "24ms"
    readonly property string motionCScramble: "600ms"
    readonly property string motionCEasing: "linear"
    readonly property string motionDDuration: "0ms"

    // --- Wallpaper texture catalogue (Out-of-plan: settings-overhaul) -----
    readonly property string textureModes: "grain noise paper leather rock fabric"
    readonly property string textureIntensityDefault: "40"
}
```

## Config/Colors.json (colour — the one thing that changes on a variant switch)

Read by `Config/Colors.qml` (a plain, never-rewritten `pragma Singleton`
whose properties this FileView updates in place). `syntax1`-`6`,
`selectionBg`/`selectionFg`/`cursorTerm` and `ansi0`-`15` are terminal-
emulator concepts with no shell surface that needs them — `Config/
Appearance.qml` does not expose them, matching Tokens.qml's own prior
"unexposed until a real consumer asks" treatment of the same fields.
