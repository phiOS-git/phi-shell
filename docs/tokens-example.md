# Config/Tokens.qml — worked example

`Config/Tokens.qml` is generated by `phi theme set` (S-12) from
`design/tokens.common.sh` + `design/tokens.<variant>.sh` in `phios-dotfiles`,
via `design/adapters.txt` (S-20). It is gitignored, so a fresh clone does not
have it until `phi theme set dark` (or `light`) has run once — see the
top-level README.

This is a hand-rendered snapshot of the dark variant as
`design/tokens.dark.sh` reads today (S-20), kept here **only** as reference
documentation — it is plain markdown, not a `.qml` file, precisely so
Quickshell's config-tree scanner never sees it as a candidate type. (A first
attempt shipped it as `Config/Tokens.example.qml`, next to the real
`Config/Tokens.qml`; Quickshell's own module scan swept it in — with or
without anything importing it — read its dotted filename's first segment as
the type name, and collided with the real `Tokens` type. `qs -p` failed to
load at all: `Config.Tokens.example - Tokens is not a type`.) This file is
not regenerated automatically and will drift from the real token files the
moment either changes — it is not a source of truth, `design/tokens.*.sh` in
`phios-dotfiles` is.

Every value is a string, units included (`"14px"`, `"120ms"`, `"1ch"`),
exactly as `design/tokens.common.sh`'s own contract requires: a consumer
that needs a bare number strips the unit itself. `Config/Appearance.qml` is
the only file allowed to read these — everything else reads `Appearance`.
